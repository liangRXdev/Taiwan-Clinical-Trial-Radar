**唯讀模式。禁止寫入或修改任何檔案，只輸出報告文字。**

第一輪跑到一半停在「引用核對」沒有輸出報告。這一輪**只做一件事**：
把 `.ai-review/plan.md` §17 的驗收條件 **A1–H5 逐條**比對實作與測試，輸出一張表。

**先輸出表，再補細節。** 不要等全部查完才開口——每查完一群（A、B、C、D、E、F、G、H）
就先把該群的結果講完，再查下一群。**寧可表格粗一點也要有完整的表。**

## 專案前提（若你的判斷與這些衝突，請明說衝突）

- 唯一 normative 規格是 `.ai-review/plan.md` **v0.9**。`Taiwan-Clinical-Trial-Radar-spec.md`
  與 v0.2–v0.8 是歷史文件，不得作為驗收依據。
- 只用 TFDA dataset 205；206–209 永久不納入。
- **同日多筆不做 tie-break**（實測 846 組平手／143 組正規化後仍衝突），
  衝突欄位在卡片上**完全省略**而非給 null。建議「取最新一筆／取非空最多者／依 CSV 列序」
  一律是誤判。
- **近似 protocol 只揭露不自動合併**（18 組）；identity 正規化刻意不剝標點、不壓內部空白。
- 三套正規化（identity／search／conflictText）刻意不共用。
- 無後端、無資料庫、無 runtime API；全部 build-time 靜態 JSON ＋ 瀏覽器端檢索。
- **風險排序：誤導 > 資料正確性 > XSS。漏報比誤報嚴重。**
- 本專案的失效模式是**假綠燈**（斷言錨錯位置、恆真斷言、sentinel 讓變異假死），
  不是測試過多。「測試可精簡」不是有效發現。

## 要輸出的表

| 驗收編號 | 規格要求（一句話） | 對應實作 file:line | 對應測試 file:line | 判定 | 說明 |
|---|---|---|---|---|---|

**判定只用這四種**：

- `符合` — 實作與測試都真的做到規格說的那件事
- `弱化` — 有測試，但 oracle 驗的是比規格更弱的性質（例如規格要「精確集合相等」，
  測試用 `toContain`；規格要「每一個 X 各一組」，測試只涵蓋其中幾個）
- `缺測` — 實作可能有，但**沒有任何測試**對應這條
- `未實作` — 規格宣稱有，實作根本沒有

**A1–H5 每一條都要出現在表裡，不得略過。** 不確定的寫 `待查` 並說明卡在哪裡。

## 重點形態（第一輪已確認的兩個，供你校準嚴重度）

第一輪找到並經覆核**確認屬實**的兩項，可作為你判斷「弱化」的參考基準：

1. **`src/ui/card.ts` 的 §7.2 命中日期**：命中來自非最新紀錄時，標籤顯示的是
   `trial.latestSourceDate`（Trial 的最新日期），而不是命中那筆紀錄的日期。
   顯示了一個不屬於該紀錄的日期——直接誤導。
2. **`src/app.ts` 的 §8.5 scope 退回**：`onNavigate` 忽略 `ensureScopeFiles` 的回傳值，
   載入失敗時 `state.scope` 仍是新的、`searchFiles` 可能只載入一半，
   畫面卻宣稱「已退回原本的搜尋範圍」。對應的 e2e 測試只斷言那句**寫死的錯誤訊息文字**
   有出現，從未檢查 state 是否真的退回——**一條恆真的斷言**。

請用同樣的標準找其餘的。
